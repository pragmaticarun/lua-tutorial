# Learn Lua: From Foundations to Embedding

A hands-on Lua course for systems developers (C++, Rust, Android, multimedia),
built with MkDocs Material. Every code sample is a real file that CI runs on
**Lua 5.5.1**, **Lua 5.4.9** and **LuaJIT 2.1** (C and C++ examples are compiled
against each one, Rust examples are built with `mlua` for each one), and the
output shown in the docs is the expected output the tests compare against.

## Status

- Part 1 (Foundations, lessons 1–9): written and tested.
- Part 2 (The Lua Way, lessons 10–17): written and tested.
- Part 3 (Systems Lua, lessons 18–22): written and tested, including C, C++ and Rust examples.
- Part 4 and Projects: outlined, coming soon.

## Quick start

```bash
sudo apt install build-essential curl git python3-venv   # gcc, g++, make
curl https://sh.rustup.rs -sSf | sh -s -- -y --profile minimal   # Lesson 22 only
scripts/install-interpreters.sh          # builds lua5.5, lua5.4, luajit under /opt
tests/run_all.sh                         # builds and runs every example on every interpreter
tests/bench.sh                           # re-measures the Lesson 17 and 19 benchmarks
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/mkdocs serve                   # http://127.0.0.1:8000
```

## Repository layout

| Path | What |
|---|---|
| `docs/` | Markdown pages |
| `examples/NN-slug/` | Lua, C, C++ and Rust snippets, `.expected` outputs, stdin inputs |
| `includes/badges/` | Per-lesson "Tested with" badges (generated) |
| `tests/run_all.sh` | Test runner: builds C/C++/Rust examples per interpreter, runs everything, pass/fail per interpreter and language |
| `includes/bench/` | Measured benchmark tables (generated by `tests/bench.sh`) |
| `scripts/install-interpreters.sh` | Builds the three interpreters (used by CI) |
| `.github/workflows/site.yml` | Test, build (`--strict`) and deploy to GitHub Pages |

See [CONTRIBUTING.md](CONTRIBUTING.md) for the authoring conventions.

## Deploying

The workflow deploys with `actions/deploy-pages`. In the GitHub repository
settings, set **Pages → Build and deployment → Source** to **GitHub Actions**.
