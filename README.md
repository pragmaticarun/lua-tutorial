# Learn Lua: From Foundations to Embedding

A hands-on Lua course for systems developers (C++, Rust, Android, multimedia),
built with MkDocs Material. Every code sample is a real file that CI runs on
**Lua 5.5.1**, **Lua 5.4.9** and **LuaJIT 2.1** (C and C++ examples are compiled
against each one, Rust examples are built with `mlua` for each one), or inside
the **real host application** for Part 4 (Neovim, LÖVE, Redis, OpenResty, mpv,
LuaRocks/busted/luacheck/StyLua), and the output shown in the docs is the
expected output the tests compare against.

## Status

- Part 1 (Foundations, lessons 1–9): written and tested.
- Part 2 (The Lua Way, lessons 10–17): written and tested.
- Part 3 (Systems Lua, lessons 18–22): written and tested, including C, C++ and Rust examples.
- Part 4 (Real World, lessons 23–28): written and tested against the real hosts:
  Neovim 0.12.6, LÖVE 11.5, Redis 8.10.3, OpenResty 1.31.8.1, mpv 0.42.0,
  LuaRocks 3.13.0 + busted 2.3.0 + luacheck 1.2.0, StyLua 2.6.0.
- Projects (P1–P6): written and tested. A LuaRocks CLI log analyzer with busted
  specs (Lua 5.5/5.4/LuaJIT), an mpv bookmark plugin (tested in mpv), a Neovim
  notes/task plugin (headless Neovim), a LÖVE arcade game (logic on all three
  interpreters plus a real LÖVE frame run), a sandboxed C++ media pipeline
  (CMake, built against 5.5, 5.4 and LuaJIT) and its Rust/mlua twin.

## Quick start

```bash
sudo apt install build-essential curl git python3-venv   # gcc, g++, make
curl https://sh.rustup.rs -sSf | sh -s -- -y --profile minimal   # Lesson 22 and Project 6
sudo apt install cmake                    # Project 5
scripts/install-interpreters.sh          # builds lua5.5, lua5.4, luajit under /opt
sudo apt install xvfb xauth libgl1 libegl1 libgl1-mesa-dri libssl-dev unzip   # Part 4 hosts
scripts/install-hosts.sh                 # pinned Neovim, Redis, OpenResty, mpv, LÖVE, LuaRocks, StyLua
tests/run_all.sh                         # every example on every interpreter, and every host test
tests/bench.sh                           # re-measures the Lesson 17 and 19 benchmarks
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/mkdocs serve                   # http://127.0.0.1:8000
```

## Repository layout

| Path | What |
|---|---|
| `docs/` | Markdown pages |
| `examples/NN-slug/` | Lua, C, C++ and Rust snippets, `*.test.sh` host drivers, `.expected` outputs, stdin inputs |
| `projects/pN-slug/` | The six complete projects (source, tests, steps, exercises), included into the project pages |
| `includes/badges/` | Per-lesson "Tested with" badges (generated) |
| `tests/run_all.sh` | Test runner: builds C/C++/Rust examples per interpreter, runs everything (including host tests), pass/fail per interpreter, language and host |
| `includes/bench/` | Measured benchmark tables (generated by `tests/bench.sh`) |
| `scripts/install-interpreters.sh` | Builds the three interpreters (used by CI) |
| `scripts/install-hosts.sh`, `scripts/hosts/` | Installs the pinned Part 4 hosts under `/opt/hosts` (used by CI, cached) |
| `.github/workflows/site.yml` | Test, build (`--strict`) and deploy to GitHub Pages |

See [CONTRIBUTING.md](CONTRIBUTING.md) for the authoring conventions.

## Deploying

The workflow deploys with `actions/deploy-pages`. In the GitHub repository
settings, set **Pages → Build and deployment → Source** to **GitHub Actions**.
