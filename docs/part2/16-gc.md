## Intuition: tracing, not reference counting

Lua frees an object when it can no longer be **reached** from the roots (the
registry, the main thread's stack and globals, upvalues of live closures). It is
a tracing mark-and-sweep collector, so cycles are never a problem, unlike
`std::shared_ptr` or `Rc` cycles. The price is that you do not know *when* an object
is freed, which is why deterministic cleanup uses `<close>` (Lessons 10 and 13), not `__gc`.

!!! note "For C++/Rust developers"
    There is no destructor at scope exit. `__gc` is like a Java finalizer or a
    `Drop` impl that runs "eventually, on some later allocation". Weak tables are
    Lua's `std::weak_ptr` / `Weak<T>`: a reference that does not keep the object alive.

## Incremental vs generational

- **Incremental** (the only mode in 5.1–5.3 and LuaJIT): each cycle marks every
  live object, interleaved with your code in small steps so pauses stay short.
- **Generational** (5.4+): most objects die young, so frequent *minor*
  collections only look at recently created objects, with an occasional *major*
  collection. It usually cuts GC time for allocation-heavy code (parsers,
  string building); it can be worse for programs whose old data changes constantly.

## Weak tables

A table's metatable field `__mode` makes its keys (`"k"`), values (`"v"`) or both
(`"kv"`) weak: these references do not keep objects alive, and entries whose
object is collected disappear.

Since Lua 5.2 a weak-key/strong-value table is an **ephemeron table**: a value is
only marked if its key is reachable some other way. LuaJIT keeps 5.1 semantics,
so the strong value keeps the key alive and the entry is never removed. On
LuaJIT, avoid side-table values that reference their key (store an id instead),
or the "leak-free" side table leaks.


```text
--8<-- "examples/16-gc/finalizers.expected"
```

Rules worth remembering:

1. An object is *marked for finalization* only if its metatable already has a
   `__gc` field when `setmetatable` is called. Adding `__gc` later does nothing
   (set it to any placeholder, e.g. `true`, then replace it).
2. Finalizers run in reverse order of marking, after the collection that found
   the object dead, and never more than once per object.
3. The object is still usable inside the finalizer and can be resurrected; weak
   *values* referring to it are cleared before the finalizer runs, weak *keys* after.
4. All pending finalizers run when the state is closed (normal script exit, `lua_close`).
5. Errors inside a finalizer become warnings (`warn`, 5.4+); they do not propagate.

Lua 5.1 and LuaJIT honour `__gc` only on userdata. From Lua, the undocumented
`newproxy(true)` creates one; with the FFI, `ffi.gc(cdata, fn)` is the standard way
to tie a C resource (a `malloc`ed buffer, an `AVFrame*`) to the collector.

!!! warning "Do not rely on finalizers for scarce resources"
    The collector runs according to memory pressure on the Lua heap, which knows
    nothing about file descriptors, GPU textures or memory allocated by C. A
    1 KiB userdata wrapping a 30 MiB frame looks cheap to the GC. Close such
    resources explicitly (`<close>`, `:close()`), and keep `__gc` as a safety net
    (Exercise 4).

## Quiz

??? question "Q1. Can two tables that reference each other leak in Lua?"
    No. The collector traces reachability from the roots, so unreachable cycles are collected.

??? question "Q2. Why does a weak-valued table keep the entry `t[1] = \"text\"` forever?"
    Strings are values, not objects, as far as weak tables are concerned; only
    tables, functions, userdata and threads are removed.

??? question "Q3. You add `mt.__gc = f` after `setmetatable(obj, mt)`. What happens?"
    Nothing: `obj` was not marked for finalization because the metatable had no
    `__gc` field at `setmetatable` time.

??? question "Q4. A weak-key table maps objects to `{ owner = obj }`. Does it leak?"
    Not on Lua 5.2+ (ephemeron table). On LuaJIT/5.1, yes: the strong value keeps the key alive.

??? question "Q5. How do you change the GC pause on Lua 5.5?"
    `collectgarbage("param", "pause", value)`. `setpause` no longer exists in 5.5.
